# LMS/ERP Sync — User Stories

**Module:** `14-lms-erp-sync`
**Status:** 📝 Spec drafted 2026-09-30
**Owner:** Rahul (product owner)
**Last updated:** 2026-09-30

---

## 1. Purpose

Gives School Admins two self-serve ways to keep the platform roster in step with the school's own systems (`brd.md` §4 in-scope LMS/ERP sync, PRD §3 Phase 2/3): a portal-generated CSV/Excel upload with dry-run validation, and inbound REST webhooks for live sync. Both are idempotent, produce row-level reconciliation reports, and sit behind the B2B SaaS licence gate (`brd.md` §7).

## 2. Actors

| Actor | What they do in this module |
| --- | --- |
| Student / Guardian / Teacher | No direct surface — may be created PENDING or updated by roster rows/events; verification still flows through module 03 |
| School Admin | Downloads the template, uploads CSV/Excel, reviews dry-run reports, commits imports, registers/tests/rotates ERP endpoints, reads event logs + reconciliation |
| Super Admin | No routine surface — owns the per-school sync licence flag (via 07) and reads audit trails |
| Vendor / EdTech brand | No access — nothing in this module is vendor-reachable |
| School's LMS/ERP system | External counterparty: POSTs HMAC-signed events (`student.upserted`, `enrollment.changed`, `staff.upserted`) to `POST /api/v1/webhooks/erp/{schoolId}` |
| System (jobs, webhooks) | Runs import validation/commit jobs (01 `jobs`), records audit entries, enforces replay window + rate limits |

## 3. Scope

**In scope**

- Portal-generated roster template (fixed English machine headers + bn/en instruction sheet, sections pre-filled).
- Self-serve CSV/Excel upload (`dry_run=true|false`); async processing > 500 rows via 01 `jobs`.
- Dry-run validation report (row-level errors: bad phone, unknown section, duplicate-in-file) + error CSV.
- Commit in chunks of 500: users upserted via 03 (created users PENDING — never auto-verified), enrollments via 04 `CreateEnrollments`; totals + reconciliation summary.
- Idempotent ingestion: content-hash (same file = no-op) and `X-Kushol-Event-Id` (replayed event = duplicate).
- ERP webhook endpoints: register (secret shown once, bn+en warning), test event, rotation (versioned + overlap), revoke, delivery log, redrive (P1).
- Inbound webhook ingestion — unauthenticated-but-HMAC-signed (documented exception, module 12 pattern): HMAC-SHA256, ±5-min window, 60 events/min/school.
- Monthly reconciliation report (last import vs platform roster, drift flagged); bn/en i18n (`sync.*`, `validation.*`).

**Out of scope** (explicit — prevents scope drift)

- Verification decisions — module 03 (`verification_requests` never written here).
- Enrollment/group/topic application internals — the 04/05/06 chain (14 calls 04 exports only).
- Outbound sync to schools' systems — inbound only at launch.
- Fee/payment, ads, marketplace sync — modules 12/13/10/11.
- mTLS/OAuth webhook auth — HMAC-SHA256 chosen (README default); revisit needs an ADR.
- Mobile app screens — web-only (README scope `api` `web`).

**Depends on**

| Module | What this module needs from it |
| --- | --- |
| 03 identity-access | Exported user upsert (see 06-integration §3 there) consumed as `users.UpsertRosterUser`; PENDING/VERIFIED semantics |
| 04 organization-hierarchy | `hierarchy.CreateEnrollments(batch, source)` + `hierarchy.GetSection`; verified-user group/topic chain |
| 05 media | Roster file storage (`media_assets` presign + confirm) |
| 01 foundations | `jobs.Enqueue`/`Register`, `audit.Record`, RFC-7807 envelope, rate-limit middleware |
| 07 command-center-web + shared | `/school/roster` + `/school/integrations` nav stubs (14 fills both); `sync.*`/`validation.*` bn + en catalogs |

## 4. User Stories

### `LMS-US-001` — Download the portal-generated roster template

**Priority:** P0 · **Traces:** `brd.md` §4 / README module 07 default · **Depends on:** 04 sections

**Story** — As a **School Admin**, I want **to download a template generated by the portal with the exact columns and my school's current sections pre-filled**, so that **my office staff can fill it without guessing the format**.

**Acceptance criteria**

- **Given** my school's ACTIVE sections, **when** `GET /api/v1/school/roster/template` is called, **then** a CSV downloads with the fixed English header set and current (classLevel, section, session) rows pre-filled.
- **Given** any locale, **when** the file opens, **then** it carries bn + en instruction rows (column meanings, phone format); headers stay English-only machine format (`LMS-BR-008`).
- **Given** an unauthenticated/non-admin caller, **when** called, **then** `UNAUTHENTICATED`/`FORBIDDEN` — no file.

### `LMS-US-002` — Upload a roster file (async, idempotent)

**Priority:** P0 · **Traces:** PRD §3 Phase 2 basic migration · **Depends on:** `LMS-US-001`, 05 media

**Story** — As a **School Admin**, I want **to upload my roster as CSV or Excel with large files processed in the background — and identical re-uploads treated as no-ops**, so that **a 5,000-row roster never times out and a double-click cannot corrupt anything**.

**Acceptance criteria**

- **Given** a valid file ≤ 10,000 rows (`LMS-BR-007`, `TODO: Confirm`), **when** `POST /api/v1/school/roster/imports` is called with `dry_run=true`, **then** the file is stored via 05 media, an import row is created, and a validation job is enqueued.
- **Given** a file > 500 rows, **when** accepted, **then** processing is async — the response carries id + status `uploaded`; the UI polls to `ready`/`validated_with_errors`.
- **Given** the identical file re-uploaded to my school, **when** its SHA-256 matches an existing import, **then** the original import returns (200) — no new job, rows, or import row (`LMS-BR-002`); the same content from a *different* school is a separate import.

### `LMS-US-003` — Review the dry-run report and fix errors

**Priority:** P0 · **Traces:** README module 07 default (strict headers, row-level report) · **Depends on:** `LMS-US-002`

**Story** — As a **School Admin**, I want **a row-level validation report naming each bad row (invalid phone, unknown section, duplicate-in-file) downloadable as CSV**, so that **I fix the source file and re-upload before anything changes**.

**Acceptance criteria**

- **Given** a finished dry-run with errors, **when** `GET …/imports/{id}/rows?result=error` is called, **then** each row carries `rowNo`, i18n `errorKey`, and a locale-aware message (bn default), downloadable as an error CSV.
- **Given** a dry-run, **when** validation finishes, **then** zero errors → `ready` (commit enabled); any error → `validated_with_errors` (commit blocked, `LMS-BR-003`).

### `LMS-US-004` — Commit a clean import and see the reconciliation summary

**Priority:** P0 · **Traces:** PRD §3 Phase 2 · **Depends on:** `LMS-US-003`, 03/04 exports

**Story** — As a **School Admin**, I want **to commit the validated import so users and enrollments are applied, and see exactly how many were created, updated, skipped or errored**, so that **I trust what actually changed**.

**Acceptance criteria**

- **Given** an import in `ready`, **when** `POST …/imports/{id}/commit` is called, **then** a job applies rows in chunks of 500 — per row: phone-matched users updated, unmatched created **PENDING**, enrollments upserted via `hierarchy.CreateEnrollments` (`LMS-BR-005`, `LMS-BR-006`).
- **Given** some rows fail at commit (e.g. 03/04 rejects), **when** the chunk finishes, **then** the import completes with per-row `error` results and accurate totals — per-row transactionality, all outcomes reported (`LMS-BR-004`).
- **Given** commit finished, **when** I open the detail, **then** the summary shows created/updated/skipped/errored; verified users' group/topic updates run via the existing 04/05/06 chain.

### `LMS-US-005` — Register an ERP webhook endpoint

**Priority:** P0 · **Traces:** PRD §3 Phase 3 / `brd.md` §7 licence hook · **Depends on:** licence flag

**Story** — As a **School Admin**, I want **to register my ERP's webhook endpoint and receive a generated HMAC secret shown exactly once with a bilingual warning**, so that **only my school's system can authenticate events**.

**Acceptance criteria**

- **Given** name + HTTPS URL, **when** `POST /api/v1/school/erp/endpoints` is called, **then** an endpoint (v1 secret) is created; the raw secret appears once — only ciphertext is stored (`LMS-BR-009`).
- **Given** the reveal modal, **when** shown, **then** the bn+en warning ("never shown again — store it now") requires acknowledgement.
- **Given** no active sync licence, **when** registering, **then** `FORBIDDEN` with the licence message (`LMS-BR-014`).

### `LMS-US-006` — Send a test event to the registered ERP

**Priority:** P0 · **Traces:** README module 14 (test button) · **Depends on:** `LMS-US-005`

**Story** — As a **School Admin**, I want **a "send test event" button that POSTs a signed test payload to my ERP URL with success/failure feedback**, so that **I prove the integration before relying on live events**.

**Acceptance criteria**

- **Given** an ACTIVE endpoint, **when** `POST …/endpoints/{id}/test` is called, **then** an HMAC-signed `test` payload is POSTed to the endpoint URL and the outcome (HTTP status/timeout) is returned as bn+en success ("টেস্ট সফল হয়েছে" / "Test event succeeded") or failure with reason.
- **Given** a revoked endpoint, **when** tested, **then** `NOT_FOUND`/`FORBIDDEN` — no outbound call.

### `LMS-US-007` — LMS sends a live `student.upserted` event

**Priority:** P0 · **Traces:** PRD §3 Phase 3 advanced migration · **Depends on:** `LMS-US-005`

**Story** — As a **school's LMS/ERP**, I want **a validly signed `student.upserted` event applied — user upserted, enrollment changed — with verified users' groups/topics updated via the platform chain**, so that **the roster tracks admissions and section moves live**.

**Acceptance criteria**

- **Given** a valid `X-Kushol-Signature`, fresh timestamp, new event id, **when** `POST /api/v1/webhooks/erp/{schoolId}` arrives, **then** the event applies via `users.UpsertRosterUser` (+ 04 for enrollment changes) and is logged `applied` with 200.
- **Given** the student is already VERIFIED, **when** the enrollment changes, **then** groups/topics update via the existing 04/05/06 chain — never by this module directly.
- **Given** a `{schoolId}` with no ACTIVE endpoint, **when** the event arrives, **then** `INVALID_SIGNATURE`-class rejection + security log (unauthenticated-but-HMAC route by design, module 12 exception pattern).

### `LMS-US-008` — Replayed event is a duplicate, not a re-application

**Priority:** P0 · **Traces:** persona idempotent ingestion · **Depends on:** `LMS-US-007`

**Story** — As a **school's ERP retrying after a network blip**, I want **a replayed event (same `X-Kushol-Event-Id`) to return the original result without applying twice**, so that **retries are safe**.

**Acceptance criteria**

- **Given** event id E already applied, **when** E arrives again (valid signature), **then** 200 `status=duplicate`, nothing re-applied (`LMS-BR-011`); the log records the duplicate.
- **Given** the same id from a *different* endpoint, **when** received, **then** it is new — uniqueness is per (endpoint, event id).

### `LMS-US-009` — Tampered signatures and stale timestamps are rejected

**Priority:** P0 · **Traces:** `brd.md` §6 / README module 14 default (5-min window) · **Depends on:** `LMS-US-007`

**Story** — As a **platform operator**, I want **HMAC-mismatched requests rejected 403 `INVALID_SIGNATURE` and stale (±5 min) requests rejected `STALE_TIMESTAMP`, both security-logged**, so that **forged or replayed-later requests cannot enter the platform**.

**Acceptance criteria**

- **Given** a body/signature mismatch, **when** received, **then** 403 `INVALID_SIGNATURE` via constant-time compare (`LMS-BR-009`), event logged `rejected` (`signature_valid=false`) + audit entry.
- **Given** `X-Kushol-Timestamp` older than 5 minutes (valid signature), **when** received, **then** 400 `STALE_TIMESTAMP`, logged `rejected`; the ERP re-signs with a fresh timestamp + new event id.
- **Given** repeated failures, **when** thresholds trip, **then** default rate limiting + module 15 alerting apply — no duplicated lockout logic.

### `LMS-US-010` — Rotate an endpoint secret with graceful overlap

**Priority:** P1 · **Traces:** README module 14 (rotating, versioned secrets) · **Depends on:** `LMS-US-005`

**Story** — As a **School Admin**, I want **to rotate the secret while the old one keeps working through an overlap window**, so that **rotation never drops live events during my ERP's redeploy**.

**Acceptance criteria**

- **Given** an ACTIVE endpoint on v1, **when** `POST …/rotate-secret` is called, **then** a v2 secret is generated (raw shown once, ciphertext stored), v1 stays valid until the overlap expires (24 h default).
- **Given** the overlap expired, **when** a v1-signed event arrives, **then** `INVALID_SIGNATURE`; the log names the failed version.

### `LMS-US-011` — Delivery log and failed-event redrive

**Priority:** P1 · **Traces:** README module 14 (applied log, redrive) · **Depends on:** `LMS-US-007`

**Story** — As a **School Admin**, I want **a per-endpoint event log (type, status, time, reason) and one-click redrive for failed events**, so that **I see sync health and recover from an ERP-side bad deploy**.

**Acceptance criteria**

- **Given** received events, **when** `GET …/endpoints/{id}/events` is called, **then** a paged log returns type, status, time, reject reason; `last_success_at` shows on the endpoint.
- **Given** an `error` event, **when** redriven, **then** `ApplyErpEvent` re-runs on the stored payload and transitions to `applied` or stays `error` with a fresh reason — never applied twice.

### `LMS-US-012` — Monthly reconciliation report flags roster drift

**Priority:** P1 · **Traces:** README module 14 (reconciliation reports) · **Depends on:** `LMS-US-004`

**Story** — As a **School Admin**, I want **a monthly report comparing my last import's counts against the platform's current roster with drift flagged**, so that **departed students, missed section moves, or quiet import failures surface**.

**Acceptance criteria**

- **Given** my school's history, **when** `GET /api/v1/school/roster/reconciliation` is called, **then** it returns last-import totals vs current ACTIVE platform counts per section with drift flagged.
- **Given** no import ever ran, **when** requested, **then** the platform counts return with an explicit "no baseline" state — not an error.

## 5. Business Rules

| ID | Rule | Enforced where |
| --- | --- | --- |
| `LMS-BR-001` | Tenant isolation: imports/endpoints/events scoped to the caller's `schoolId` claim; webhook tenant = `{schoolId}` in the URL verified against an ACTIVE endpoint row | Service + repository (both) |
| `LMS-BR-002` | Content idempotency: `content_sha256` UNIQUE per school — re-upload returns the original import, no side effects | DB unique index + service |
| `LMS-BR-003` | Commit requires status `ready` (clean dry-run); `validated_with_errors` blocks commit | Service |
| `LMS-BR-004` | Row results immutable once written; per-row independent — a failing row never rolls back siblings; final status reports all outcomes | Repository (no result UPDATE) + service |
| `LMS-BR-005` | Roster ingestion NEVER auto-verifies: created users are PENDING; module 03's verification flow applies untouched; `verification_requests` never written | Service (03 contract) |
| `LMS-BR-006` | Match rule: phone = identity key — matched → update, unmatched → create PENDING. `TODO: Confirm` secondary (email) match | Service (03 upsert path) |
| `LMS-BR-007` | Max 10,000 rows/file (`TODO: Confirm`); > 500 rows async via 01 jobs | Service + job |
| `LMS-BR-008` | CSV headers are a fixed English-only machine set, validated exactly (names + order); UI/template instructions bn+en | Service (parser) |
| `LMS-BR-009` | Webhook secrets: HMAC-SHA256, per-endpoint, versioned, rotating; constant-time compare; stored AES-256-GCM encrypted (`ERP_SECRET_KEY`, config module only); raw shown exactly once | Service + DB |
| `LMS-BR-010` | Replay window: `X-Kushol-Timestamp` within ±5 minutes or rejected `STALE_TIMESTAMP` | Webhook middleware |
| `LMS-BR-011` | Event idempotency: `X-Kushol-Event-Id` (UUID) UNIQUE per endpoint — duplicates return 200 `duplicate` (original result), no re-application | DB unique index + service |
| `LMS-BR-012` | Rate: max 60 webhook events/min/school → 429 `RATE_LIMITED` + `Retry-After` | Rate-limit middleware |
| `LMS-BR-013` | Only ACTIVE endpoints accept events; revoked/unknown rejected + security log; rotation keeps the previous version valid until overlap expiry | Service |
| `LMS-BR-014` | Licence gate: sync features require the school's sync licence flag (`brd.md` §7 B2B SaaS); without it `FORBIDDEN` + licence message | Service (flag via 07/Super Admin) |

## 6. Validation Rules

| Field | Rule | Message key (`packages/shared` i18n catalog) |
| --- | --- | --- |
| upload `file` | required; csv/xlsx magic bytes; ≤ 20 MB; ≤ 10,000 data rows | `validation.required` · `sync.import.format_invalid` · `sync.import.too_large` · `sync.import.rows_exceeded` |
| CSV header row | exact fixed set + order (`full_name,phone,role,class_level,section_name,session_year`) | `sync.import.headers_invalid` |
| row `phone` | Bangladesh mobile `01[3-9]\d{8}` (normalized digits) | `validation.phone.invalid` |
| row `full_name` / `role` | name required 2–120 chars; role ∈ `STUDENT \| TEACHER` | `validation.required` · `sync.row.name_invalid` · `sync.row.role_invalid` |
| row `class_level`+`section_name` | resolve to an ACTIVE section of the caller's school + session | `sync.row.section_unknown` |
| row duplicates | same phone twice in one file → second is `duplicate_in_file` | `sync.row.duplicate_in_file` |
| endpoint `name` / `url` | name 1–80 chars; url HTTPS-only, ≤ 500 chars | `sync.endpoint.name_invalid` · `sync.endpoint.url_invalid` |
| webhook headers | `X-Kushol-Signature` (`sha256=<hex>` over `{timestamp}.{rawBody}`), `-Timestamp` (±5 min), `-Event-Id` (UUID) all required | `sync.webhook.headers_missing` (server codes `INVALID_SIGNATURE`/`STALE_TIMESTAMP`/`VALIDATION_FAILED`) |
| list `page`/`pageSize` | page ≥ 1; 1 ≤ pageSize ≤ 100 | `validation.page_invalid` |

## 7. Edge Cases & Negative Paths

| # | Scenario | Expected behaviour |
| --- | --- | --- |
| 1 | Unauthenticated call to any `/school/roster/*`, `/school/erp/*`, `/school/roster/reconciliation` | `UNAUTHENTICATED`, no side effect |
| 2 | School Admin A addresses school B's import/endpoint/event | `TENANT_MISMATCH` (404 body), nothing leaked |
| 3 | Webhook to unknown/revoked `{schoolId}` endpoint | `INVALID_SIGNATURE` rejection + security log; nothing applied |
| 4 | Commit job crashes mid-commit | Resume by row cursor; processed rows skipped (immutable results) |
| 5 | 03/04 export rejects rows at commit | Per-row `error`; import completes `committed` with true totals (`LMS-BR-004`) |
| 6 | Wrong/extra/reordered headers; file > 10,000 rows / > 20 MB; object missing at process time | File `failed` (`sync.import.headers_invalid`) or `VALIDATION_FAILED` at upload; re-upload, never a crash |
| 7 | Event references an unknown section | User-upsert part applies; enrollment part `error` (`sync.row.section_unknown`); redrive later |
| 8 | Same event id from a different endpoint; 61st event in a minute | New event (uniqueness per endpoint+id); 429 `RATE_LIMITED` + `Retry-After`, not logged `applied` |
| 9 | XLSX formulas/merged cells; reduced motion; offline (web) | Values only (formulas never executed); static step transitions; submit disabled + reconnect message |

## 8. Reporting Needs

- Import totals (rows/created/updated/skipped/errored) per school — 07 dashboard cards + history table.
- Reconciliation drift (last import vs platform roster per section) — `GET /school/roster/reconciliation`; flags only, no auto-correction.
- Endpoint health (`last_success_at`, applied/duplicate/rejected/error counts) — 07 integrations table; feeds module 15 alerting.
- Security counters (rejected signatures, stale timestamps) — audit log (01) + monitoring; never cross-tenant visible.
